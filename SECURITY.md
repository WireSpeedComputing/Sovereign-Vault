# Security reporting

Report suspected vulnerabilities using this repository's
[private vulnerability reporting form](https://github.com/WireSpeedComputing/Sovereign-Vault/security/advisories/new).
Do not put exploit details or deployment findings in public issues or pull
requests.

Include the affected source revision, prerequisites, a minimal synthetic
reproduction, expected and actual behavior, impact limits, and proposed
remediation when available. Distinguish reference-code findings from confirmed
deployment findings. Never include credentials, tokens, business rows, or real
principal and project identifiers. Private advisories can later be published;
reports should remain safe to sanitize for coordinated disclosure.

If private reporting is unavailable, keep the finding in private operational
records until an approved private channel is available. Do not use a public
issue as a fallback.

Read [STATUS](STATUS.md#known-open-risks) before deployment. Existing replay
and synthetic acceptance evidence is not a guarantee of end-user identity
enforcement or enterprise readiness.
